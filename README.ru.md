# 📚 BookFlow API

🇬🇧 [English](./README.md) | 🇷🇺 [Русский](./README.ru.md)

RESTful API-сервис для учета личной библиотеки. Позволяет пользователям формировать общий каталог книг, добавлять их на личную полку со статусами чтения, выставлять оценки, фильтровать записи и получать топ книг по рейтингу.

## 🛠 Технологический стек

* **Язык:** Python 3.11+
* **Фреймворк:** FastAPI
* **Валидация и конфигурация:** Pydantic v2, pydantic-settings
* **База данных и ORM:** PostgreSQL 16, SQLAlchemy 2.0 (asyncpg), Alembic
* **Кэширование:** Redis 7
* **Аутентификация:** JWT-токены (OAuth2 Password Flow), хэширование паролей (bcrypt)
* **Тестирование:** Pytest, HTTPX (`AsyncClient`)
* **Контейнеризация:** Docker, Docker Compose

## ✨ Основной функционал и архитектурные решения

* **Пользователи и авторизация:** регистрация, аутентификация по OAuth2 с выдачей JWT-токена и просмотр данных текущего профиля.
* **Каталог книг (CRUD):** добавление книг, просмотр с пагинацией (`limit`/`offset`) и фильтрацией, получение топа книг по среднему рейтингу. Редактирование и удаление доступны только создателю записи (проверка прав доступа).
* **Личная полка:** добавление книг на полку со статусом (*планирую прочитать*, *читаю*, *прочитано*), изменение статуса и выставление оценок, фильтрация полки по статусам.
* **Кэширование с версионированием ключей (Redis):** выборка топа книг (`/api/v1/books/top`) кэшируется в Redis с привязкой к версии ключа; при добавлении или обновлении оценок на полке версия инкрементируется, а устаревшие записи автоматически удаляются по TTL без блокирующих операций поиска по маске.
* **Repository Pattern:** логика работы с базой данных и кэшем изолирована в отдельном слое (`repository.py`).
* **Кастомная обработка ошибок:** структурированные JSON-ответы при ошибках авторизации, нехватке прав (`403 Forbidden`) или отсутствии записи (`404 Not Found`).

## 🚀 Быстрый запуск (Docker)

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/alex-p-89/bookflow.git
   cd bookflow
   ```

2. **Настройте переменные окружения:**
   Создайте файл `.env` на основе шаблона и заполните его своими значениями (параметры PostgreSQL, Redis и секретный ключ JWT):
   ```bash
   cp .env.example .env
   ```

3. **Запустите проект в один клик:**
   ```bash
   docker-compose up --build -d
   ```

При запуске контейнеры PostgreSQL и Redis проходят проверку готовности (`healthcheck`), после чего автоматически применяются миграции базы данных (`alembic upgrade head`, включая начальное наполнение каталога) и запускается Uvicorn-сервер.

Сервис будет доступен по адресу `http://localhost:8000`.

## 📖 Документация API

Интерактивная документация автоматически генерируется FastAPI и доступна после запуска проекта:
* **Swagger UI:** [http://localhost:8000/docs](http://localhost:8000/docs)
* **ReDoc:** [http://localhost:8000/redoc](http://localhost:8000/redoc)

### Основные эндпоинты

| Метод | Эндпоинт | Описание | Доступ |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/auth/register` | Регистрация нового пользователя | Публичный |
| `POST` | `/api/v1/auth/login` | Авторизация и получение JWT-токена | Публичный |
| `GET` | `/api/v1/users/me` | Получение данных текущего пользователя | Авторизованный |
| `GET` | `/api/v1/books/` | Список книг с пагинацией и фильтрами | Публичный |
| `POST` | `/api/v1/books/` | Добавление новой книги в каталог | Авторизованный |
| `GET` | `/api/v1/books/top` | Топ-N книг по среднему рейтингу (с кэшем в Redis) | Публичный |
| `GET` | `/api/v1/books/{book_id}` | Детальная информация о книге | Публичный |
| `PUT` | `/api/v1/books/{book_id}` | Обновление информации о книге | Только автор записи |
| `DELETE` | `/api/v1/books/{book_id}` | Удаление книги из каталога | Только автор записи |
| `GET` | `/api/v1/shelf/` | Просмотр личной полки с фильтром по статусу | Авторизованный |
| `POST` | `/api/v1/shelf/` | Добавление книги на личную полку | Авторизованный |
| `POST` | `/api/v1/shelf/{book_id}` | Изменение статуса чтения и оценки книги | Владелец полки |

## 🧪 Запуск тестов

Тесты исключены из продакшн-контейнера (через `.dockerignore`) и запускаются локально с использованием автономной базы данных **SQLite в памяти** (`aiosqlite`), поэтому для их выполнения не требуются запущенные контейнеры PostgreSQL или Redis.

1. **Установите зависимости (если запускаете локально впервые):**
   ```bash
   pip install -r requirements.txt
   ```

2. **Запустите тесты из корня проекта:**
   ```bash
   pytest
   ```
